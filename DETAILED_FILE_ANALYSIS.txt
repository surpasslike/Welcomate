🟡 问题:
  行 54-58: 未启用 WAL 模式
    • SQLite 默认使用日志回滚模式
    • WAL 模式在多线程环境下性能更好
    • 并发写入性能会降低

修复建议:
  @Override
  public void onCreate(SQLiteDatabase db) {
      Log.d(TAG, "Creating database and users table...");
      // 启用 WAL 模式以提高并发性能
      db.enableWriteAheadLogging();
      db.execSQL(CREATE_TABLE_USERS);
      Log.d(TAG, "Database created successfully.");
  }


【app-server/src/main/java/com/surpasslike/welcomateservice/data/UserRepository.java】
════════════════════════════════════════════════════════════════════════════════
评级: 🟡 B (有安全问题)
行数: 205 行
问题数: 2 个 (1 高风险 + 1 低风险)

🔴 高风险问题:
  行 62-74: 密码使用 SHA-256 而非盐值哈希
    • SHA-256 是加密哈希，不是密码哈希
    • 没有盐值，容易被彩虹表攻击
    • 没有迭代计数，容易被暴力破解
    
  修复建议:
    1. 使用 BCrypt 库 (spring-security-crypto)
    2. 或使用 Argon2
    3. 或使用 PBKDF2 with 10000+ iterations

🟢 低风险问题:
  行 95, 100, 163-164: 使用了 @SuppressLint("Range")
    • 使用了已弃用的 getColumnIndex()
    • 虽然可以工作但不是最佳实践
    
  修复建议:
    • 迁移到 Room ORM

✅ 优点:
  • 使用了 double-checked locking 的线程安全单例
  • 使用了 volatile 修饰符
  • SQL 注入防护完美 (参数化查询)
  • 密码比对逻辑正确 (使用 equals() 而非 ==)

          if (usersLiveData == null) {
              usersLiveData = new MutableLiveData<>();
              loadUsers();
          }
          return usersLiveData;
      }
      
      private void loadUsers() {
          List<User> users = userRepository.getAllUsers();
          usersLiveData.setValue(users);
      }
  }
